# TLMS_ESD 规范说明（初稿）

> 本文根据现有代码（v0.6.1）反向整理，描述系统“做什么、为什么”。实现方式见 [design.md](design.md)。

## 1. 目标

TLMS_ESD（Pipeline Leakage Emergency Shutdown System，管道泄漏紧急停输系统）用于输油管线的泄漏防护。管线按线、段组织，段的两端设有测控点，系统持续监视并在异常时自动停输：

- **输差监视**：每一段的输差（首端流量合计减末端流量合计）大于警告值（WH）时报警，大于报警值（AH）时停输整条线。停输前有倒计时，倒计时期间可以人为中断。
- **压力监视**：每个测控点的压力大于警告值（WH）时报警，大于报警值（AH）时停输所在段，没有倒计时。压力停输可按测控点单独允许或禁止。
- **挂起**：输差防护以段为单位。段挂起后，系统不再因输差对该段执行停泵，但报警照常。通信中断、测控点工作异常（如测量设备故障）、起停泵后的一段时间等情况由系统自动挂起；人工检修测量设备时，必须手动挂起该段，避免误动作。挂起不影响压力停输。
- **集中监控与追溯**：汇总线、段、测控点的状态，提供给 HMI/SCADA 监视和操作，并记录每次联锁停输动作。

本项目只实现其中的控制器程序，测控点一侧的程序由执行器实现（见第 3 节）。

## 2. 范围

### 2.1 包含

- 读取 YAML 配置，按控制器名称运行其中一个控制器；
- 与执行器通信：Modbus TCP、Siemens S7 两种协议；
- 段级流量差报警、压力报警汇总、联锁停泵、取消停泵；
- 线级旁路、报警汇总、自动/手动停泵命令；
- 执行器参数的发布与写回、执行器命令下发；
- 联锁动作记录（CSV 持久化，经 Modbus 浏览最近 N 条）；
- 日志记录；
- 命令行工具 `tlms`，用于后台运行和管理控制器实例。

### 2.2 不包含

- 执行器的 PLC 程序（压力越限判断、泵的实际启停由执行器完成）；
- HMI 画面；
- 线级流量差（`LINE.flow_diff` 保留，未实现）。

## 3. 术语与对象模型

### 3.1 核心术语

本系统只有两类运行实体：

- **控制器（controller）**：即本程序。一个控制器是一个 TLMS 进程，按配置管理若干条线，周期采集执行器数据，做输差判断和联锁，同时作为 Modbus TCP 服务端，把全部状态提供给 HMI/SCADA。HMI/SCADA 只与控制器通信。
- **执行器（actuator）**：现场的 PLC 及其程序，不属于本项目。执行器负责采集流量、压力、温度和泵运行状态，判断压力越限，报告自身工作状态，并按控制器的命令停泵、修改参数。执行器作为 Modbus TCP 或 S7 的服务端，由控制器主动连接。

### 3.2 节点与执行器

- **节点（node）**：段两端的测控点。一个节点有自己的流量、压力、温度和泵运行状态，在执行器上占用一组数据区和一组命令区。
- 执行器与节点的关系：一个执行器通常对应一个节点，也可以包含两个或以上的节点，这些节点可以属于不同的线或段。
- 程序中的简化：控制器把每个节点当作一个独立的执行器处理。
  - 配置中 `actuators` 的每一项、代码中的每个 actuator 对象都对应一个节点；
  - 同一执行器上的多个节点写成多个 `actuators` 项，各自配置数据区和命令区，Modbus TCP 下共用 IP 和端口；
  - 控制器为每个节点维护一个节点数据块（NODE）和一个命令块（COMMAND），各占一个 Modbus 单元号。
- 因此在配置和代码中“节点”与“执行器”两个词都会出现，但基本一一对应。本文在描述控制器的处理时统一称“执行器”，指的就是这种一个节点对应一个执行器的对象。
- 配置了 `pumps` 的执行器称为带泵执行器，是停泵命令的对象。

### 3.3 控制器内的逻辑对象

以下对象只存在于控制器内部，用于组织执行器并汇总状态：

| 对象 | 说明 |
| --- | --- |
| 线（line） | 一条管线，由若干段组成，属于一个控制器。 |
| 段（section） | 一段管道，两端为节点：首端执行器（`begin_nodes`）和末端执行器（`end_nodes`）。段是输差判断、挂起和联锁的基本单位。 |
| 动作记录（action record） | 一次联锁停泵发生时的现场快照。 |

关系：控制器 1—N 线，线 1—N 段，段 N—N 执行器（同一执行器可在不同段中作为首端或末端）。

### 3.4 判断与保护的分工

| 判断 | 位置 | 处理 |
| --- | --- | --- |
| 输差超限 | 控制器 | 按段计算输差；超过 WH 并持续延时后警告，超过 AH 并持续延时后发出停泵预告并倒计时，倒计时结束后停输整条线。 |
| 压力超限 | 执行器 | 执行器判断压力越限并上报 `pressure_AH_F`，同时上报是否允许压力联锁停输（`pressure_SD_F`）；控制器只对允许压力联锁的执行器，在其压力报警且段内有泵运行时立即停输所在段，没有倒计时。 |
| 挂起 | 控制器 | 即段的 `hangon_AF`（自动挂起）和 `hangon_MF`（人工挂起），只作用于输差联锁：段挂起时不因输差停泵，倒计时期间人工挂起即中断停输。压力联锁不受挂起约束。 |

### 3.5 部署形态

- 一个控制器连接多个执行器，每个执行器上有一个或多个节点：
  - Modbus TCP：同一执行器上的节点共用 IP 和端口，按地址区分，例如第一个节点的数据位于寄存器 0、命令位于寄存器 100，下一个节点位于 200 和 300；
  - S7：数据和命令分别位于不同的 DB，例如 DB1 和 DB2。
- 控制器配置中的 `IP` 用于记录控制器自身的部署地址，程序不读取，服务端固定监听所有地址。

## 4. 配置要求

- 工作目录下的所有 `*.yaml` / `*.yml` 文件都会被读取并合并；支持 YAML 1.1 合并键（`<<`）。
- 顶层键：`controllers`、`lines`、`sections`、`actuators`。
- 控制器：
  - `name`、`records_size`（动作记录保留条数，默认 10）；
  - `modbus_server.port`；
  - `modbus_server.unit_id`：为每条线、每个段、每个执行器及 `action_records` 分配一个 Modbus 单元号。
- 线：
  - `id`、`name`；
  - `controller`：所属控制器名称；
  - `sections`：段名称列表。
- 段：
  - `id`、`name`；
  - `begin_nodes`、`end_nodes`：执行器名称列表；
  - `flow_diff_WH` / `flow_diff_WH_delay`：流量差警告上限及延时（ms）；
  - `flow_diff_AH` / `flow_diff_AH_delay`：流量差报警上限及延时（ms）；
  - `action_time`：联锁倒计时（ms）。
- 执行器（`actuators`）：
  - `id`：必须是非零数字，否则程序退出；
  - `name`、`IP`；
  - `pumps`：可选，每项形如 `"运行信号, 停止输出"`；
  - `modbus_server` 或 `s7_server` 二选一，可分别配置 `data` 与 `commands` 区域；区域起点 `start` 以字节计，Modbus 下对应寄存器 `start / 2`（例如 `start: 200` 即寄存器 100）；
  - `supported_commands`：支持的命令列表（见 5.1 命令支持配置）；
  - `endian`：字节序，默认 `BE`。
- 配置文件同时是执行器编程的依据，控制器只采用其中与自身有关的部分：
  - 控制器采用的执行器字段：`id`、`name`、`IP`、通信协议及数据 / 命令区、是否配置了 `pumps`、支持的命令列表；
  - 段与线的 ID、限值、延时、`action_time` 作为对应数据块的初始值；
  - 其余执行器字段（压力 / 温度量程与限值、`pressure_SD`、`pressure_AI`、`temperature_AI`、`flows`、泵信号地址）用于执行器编程，控制器不直接采用；
  - 执行器参数和状态以执行器上报为准，控制器负责对外发布，并按 HMI 的命令写回执行器（见 5.1）。

## 5. 功能需求

### 5.1 执行器

- 周期读取执行器数据：ID、状态字（通信 / 工作正常、泵运行、各泵状态、压力 / 温度报警使能与越限标志）、温度、压力、流量、命令响应码、参数块。
- 通信中断或数据读取失败时，经过参数 `delay_protect_time` 的延时后，分别将 `comm_OK` / `work_OK` 置为 false。
- 通信恢复后，2 s 后用执行器当前参数刷新命令块中的参数，保证 HMI 看到的参数与现场一致。
- 命令枚举：下表是命令的完整清单，控制器必须全部实现。命令名用于 HMI 点表（见 [spec-modbus.md](spec-modbus.md) 第 5 节）和执行器的命令支持配置；位号是命令在命令字中的位置，与执行器约定一致，不得改变。

  | 位 | 命令 | 作用 | 来源 |
  | --- | --- | --- | --- |
  | 0 | `stop_pumps` | 停泵 | 联锁逻辑（见 5.2） |
  | 1 | `cancel_stop` | 取消停泵，让执行器解除停泵输出 | 联锁逻辑（见 5.2） |
  | 2 | `horn` | 输出报警 | HMI |
  | 3 | `reset_horn` | 停止报警 | HMI |
  | 4 | `enable_pressure_SD` | 允许压力联锁停泵 | HMI |
  | 5 | `disable_pressure_SD` | 取消压力联锁停泵 | HMI |
  | 6 | `read_paras` | 读取参数：用执行器当前参数刷新命令块中的参数，不发送给执行器 | HMI |
  | 7 | `write_paras` | 写参数：把命令块中的参数写入执行器 | HMI |
  | 8 | `enable_pressure_alarm` | 允许压力报警 | HMI |
  | 9 | `disable_pressure_alarm` | 禁止压力报警 | HMI |
  | 10 | `enable` | 允许该执行器工作 | HMI |
  | 11 | `disable` | 禁止该执行器工作 | HMI |
  | 12 | `reset_CPU` | 重置执行器 CPU | HMI |
  | 13 | `reset_conn` | 重置连接 | HMI |

  命令字的位 14（`reserve`）保留，位 15（`executing`）是状态位，都不是命令。新增命令必须先加入本清单。

- 命令握手：
  - 命令置位后，控制器把命令字连同 ID 和参数块发送给执行器；
  - 执行器用 `response_code` 应答已执行的命令位，控制器收到后清除对应命令位；
  - 允许 / 取消压力联锁停泵命令，在执行器上报的 `pressure_SD_F` 变为对应状态时清除；
  - 连续 3 个周期没有应答时，重新发送命令。
- 停泵与取消停泵的关系：
  - 正常情况下，控制器下达 `stop_pumps` 后，执行器停泵，上报的泵运行状态变为 false，控制器即收回 `stop_pumps`，不需要 `cancel_stop`；
  - 异常情况下，泵运行状态可能一直为 true（例如状态信号故障）。这时即使控制器收回了 `stop_pumps`，执行器一侧仍保持停泵输出，而且这个输出不会因泵状态而撤销，会阻碍同一执行器上其他泵启泵；
  - 因此停泵命令撤销时，控制器必须向相关执行器发送 `cancel_stop`，由执行器解除停泵输出。
- 命令支持配置：不同执行器支持的命令可能不同。每个执行器在配置中列出自己支持的命令（取自上面的命令枚举），控制器只向执行器发送它支持的命令；不支持的命令位由控制器直接复位，不发送，HMI 看到该命令位被复位。
  - 配置字段为 `supported_commands`，值是命令名列表，命令名取自命令枚举，例如：

    ```yaml
    actuators:
    - id: 1001
      name: A1
      supported_commands:
        - stop_pumps
        - cancel_stop
    ```

  - 省略 `supported_commands` 时的默认值为支持全部命令

### 5.2 段

- `comm_OK` / `work_OK`：段内所有执行器都正常时为 true。
- `pump_run` / `pump_change_F`：任一带泵执行器有泵运行 / 泵处于启停过渡期时为 true。
- `press_warning_F` / `press_alarm_F`：任一执行器压力警告 / 报警时为 true。
- 流量：
  - `flow_begin` 为首端执行器流量之和，`flow_end` 为末端执行器流量之和；
  - `flow_diff = flow_begin - flow_end`。
- 流量差判定（段旁路 `bypass` 时不判定）：
  - 流量差持续超过 `flow_diff_WH` 达到 `flow_diff_WH_delay` 后，`flow_warning_F` 置位；
  - 持续超过 `flow_diff_AH` 达到 `flow_diff_AH_delay` 后，`flow_alarm_F` 置位。
- 保护状态：
  - 当通信正常、工作正常、无泵启停过渡、未旁路，且未被手动挂起（`hangon_MF`）时，段处于保护状态（`protect_F`）；
  - 前四个条件中任一不满足时，自动挂起（`hangon_AF`）。
- 停泵预告：
  - `flow_alarm_F`、`pump_run`、`protect_F` 同时成立时，发出停泵预告（`pre_stop_notice`），并开始 `action_time` 倒计时（`countdown`，单位 s）；
  - 倒计时结束仍满足条件时，执行流量联锁；
  - 倒计时期间任一条件消失（例如人工挂起使 `protect_F` 失效），倒计时清零，停输被中断。
- 联锁动作：
  - 流量联锁（停线）：置位段的 `action_F`，记录线的 `action_section_ID`，置位线的 `autoStopCmd`，并标记本段为线动作源（`line_action_source`）。线的停泵命令作用于线内所有段，凡有泵运行的段都会停泵；
  - 压力联锁：段内任一 `pressure_SD_F` 为真的执行器 `pressure_AH_F` 为真，且段内有泵运行时，置位段的 `action_F` 和段的 `autoStopCmd`。`pressure_SD_F` 为假的执行器只报警，不触发停泵。压力联锁不受挂起（`protect_F`）约束。目前压力联锁只停本段，将来可能扩展为停线。
  - 段的 `press_alarm_F` 仍汇总全部执行器的 `pressure_AH_F`，用于报警显示，不论是否允许压力联锁。
- 停泵：段或所属线上存在自动 / 手动停泵命令，且本段有泵运行时，向本段所有带泵执行器下发停泵命令；命令撤销时下发取消停泵命令。
- 复位：
  - 泵全部停止后，清除段的 `autoStopCmd` / `manStopCmd`；
  - 泵重新启动时，如果报警已消失、且不是由停泵命令维持的动作，自动清除 `action_F` 和线的 `action_section_ID`。
- 每次 `action_F` 置位都生成一条动作记录（见 5.4）。

### 5.3 线

- `pump_run`：任一段有泵运行时为 true；
- `alarm_F`：任一段流量报警或压力报警时为 true；
- `pre_stop_notice`：任一段处于停泵预告时为 true；
- `bypass`：线旁路状态下发到线内所有段；
- 线内泵全部停止后，清除线的 `autoStopCmd` / `manStopCmd`；
- `manStopCmd` 由 HMI 写入，用于手动停泵。

### 5.4 动作记录

- 内容：
  - 时间（年 / 月 / 日 / 时 / 分 / 秒）、动作段 ID；
  - 首末端流量及流量差；
  - 动作段执行器的压力、ID 和泵运行状态，固定 4 个位置（节点 1–4）；
  - 动作原因：压力原因（`press_action`）取段的 `press_alarm_F`，即全部执行器压力报警的汇总；流量原因（`flow_action`）取段的 `flow_alarm_F`。
- 执行器位置：
  - 固定 4 个位置是为了与原 PLC 控制器的数据结构兼容，不支持变长记录；
  - 4 个位置不区分首端和末端：动作段的执行器按先首端、后末端的顺序依次占用节点 1–4，例如 2 个首端执行器和 2 个末端执行器，分别占用节点 1、2 和节点 3、4；
  - 每个位置的压力、ID、泵运行状态都取自同一个执行器；
  - 段内执行器超过 4 个时，只记录前 4 个；未占用的位置为 0 / false。
- 持久化：追加写入工作目录下的 `action_records.csv`，文件不存在时自动创建。
- 浏览：内存中保留最近 `records_size` 条，HMI 写入 `index`（0 为最新）即可切换显示的记录；`index = -1` 表示无记录。

### 5.5 对上接口（Modbus TCP 服务端）

- 控制器在 `controller.modbus_server.port` 上监听，地址为 `0.0.0.0`。
- 每条线、每个段、每个执行器、动作记录各占一个单元号（unit id），对应关系由配置给出。
- 执行器单元中，从寄存器 0 开始是节点数据块，从寄存器 200 开始是命令块。
- 支持读写保持寄存器、读输入寄存器、读写线圈。HMI 的写入会立即触发相应的状态变化处理。
- 各数据块的寄存器布局由 `src/structs/` 定义，必须与 HMI 及执行器程序保持一致。完整点表见 [spec-modbus.md](spec-modbus.md)。

### 5.6 运行与运维

- 控制器以后台常驻进程运行，不依赖登录会话；同一时间只运行一个控制器实例，启动时先停止已有实例。
- 提供命令行工具 `tlms`，支持：
  - 指定配置目录和控制器名称启动（`start`），以及重启（`restart`，同 `start`）；
  - 停止（`stop`）；
  - 列出后台运行的实例（`list`）；
  - 查看日志（`log`）和清空日志（`flush`）；
  - 前台运行（`debug`），日志级别为 debug，用于调试；
  - 显示版本号和帮助。
- 控制器名称省略时，运行配置中的第一个控制器。
- 日志：
  - 普通日志和错误日志分别写入工作目录下的 `logs/info.log` 与 `logs/error.log`，按天滚动，单个文件上限 10 MB 并压缩；
  - 前台运行时同时输出到控制台；
  - 日志级别由环境变量 `LOG_LEVEL` 控制，默认 `info`。
- 未捕获的异常只记录日志，不退出进程，以保证保护功能持续运行。

## 6. 性能与时序

- 主循环周期 500 ms（`MAIN_PERIOD`），流量差延时与倒计时都以此为步长累计。
- 驱动轮询周期 1 s，断线 5 s 后重连。
- 状态汇总带 50 ms 防抖，命令发送带 100 ms 防抖。

## 7. 实现约束

- 使用 JavaScript 实现。
- 与执行器通信须支持 Modbus TCP 和 Siemens S7 两种协议；对上只提供 Modbus TCP 服务端。
- 配置文件格式为 YAML，动作记录持久化格式为 CSV。
- 运行环境、依赖库、进程管理和构建方式见 [design.md](design.md) 第 10 节。
